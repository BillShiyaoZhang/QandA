# 让用户只提供自己想分享的内容

平台的核心是交流好奇心、问题、回答与追问。记录模型之间的差异仍然有价值，但不是每个参与者都要完成的实验登记。用户可以只提问，也可以自己回答、分享已有 AI 回答，或接着某份回答继续问。

## 信息负担盘点

旧版新问题、回答、追问、关联分别展示 11、9、12、7 个字段，包含最终公开确认；此外还有站内重复确认、GitHub 顶层 Issue 标题和手填内部编号。问题的实际负担不只是必填数量，还包括看见陌生字段时必须判断“我是不是该填”。

| 场景 | 需要用户主动提供 | 可以选填 | 系统负责 | 简化后的表单项数 |
| --- | --- | --- | --- | --- |
| 新问题 | 问题内容、一次公开确认 | 已有回答、来源或背景补充 | 由第一行取展示标题，完整保留正文；账号署名、记录时间与编号 | 11 → 4 |
| 回答 | 回答正文、一次公开确认 | 来源或背景补充 | 从入口带入具体问题版本，保留投稿来源与署名 | 9 → 4，包含自动填入的位置 |
| 追问 | 追问内容、一次公开确认 | 初步回答、来源或背景补充 | 带入具体父答案，生成标题，建立分支 | 12 → 5，包含自动填入的位置 |
| 关联 | 选择另一段内容、说明理由、一次公开确认 | 主题相关默认无需摘录；支持或冲突须双方原文 | 当前内容带入、两端位置转成固定链接 | 7，两个位置由网站选择后填入 |

这些项数不计 GitHub 自带的 Issue 标题框：它已有预设值，不要求用户再次起标题。从已有内容进入时，不需要重新找位置；从参与页直接进入时，按标题、版本和回答摘要选择，不需要理解或复制内部编号。

## 每类信息的去向

| 信息 | 处理决定 | 理由 |
| --- | --- | --- |
| 问题标题 + 问题正文 | 合并为一处正文；第一行最多取 90 个字符作为标题 | 不重复问同一件事；长正文不截断、不改写 |
| 回答正文 | 必填；附在新问题或追问后的回答为选填 | 用户分享的实质内容，来源链接不能替代正文 |
| 主题标签 | 从默认提交移除，默认为空 | 不让用户先决定分类；不自动编造标签 |
| 模型名称、生成日期、规则、工具、上下文、来源链接 | 合为“来源补充（选填）”，按自然语言提供 | 知道多少写多少，不强迫查询、猜测或填写“未知” |
| 来源补充 | 原样保存为公开注释；有回答时属于该回答，否则属于问题版本 | 用户填了就保留，不因缺少附带回答而丢失 |
| 精确的模型条件 | 旧表单和结构化导入继续支持 | 自愿研究与比较场景仍能记录精确信息 |
| 回答位置、追问位置、关联端点 | 网页按内容选取并自动填入固定链接；旧编号仍能解析 | 用户核对的是内容，程序维护的是稳定引用 |
| 昵称、邮箱、职业、个人简介 | 不另外收集 | 本次参与不需要；署名采用 GitHub 账号，账号不等于正文原创作者 |
| 内容编号、录入时间、哈希、收录状态 | 系统生成 | 不应交给提交者操作 |
| 公开许可 | 最终提交时勾选一次；网站提前说明公开范围 | 保留必要确认，移除重复动作 |

“来源补充”不会被猜测性地拆成模型字段：写了模型名字，也只保留为提交者的说明。旧的结构化模型记录照常展示；没有模型声明的回答称为“社区回答”，不推断为 AI 输出或人类原创。生成时间不能用提交时间代替，未知工具状态不能写成“未使用”。

## 实际路径

1. **闪过一个问题**：点“提个新问题”→去 GitHub 写问题正文→确认公开→提交。不用先有答案、不用起两次标题。
2. **想回答正在读的问题**：点“提交本题答案”→看到已选版本与原文摘要→去写回答→确认公开→提交。
3. **看完回答又有疑问**：点“追问这份回答”→看到对应回答→写追问→提交；可顺手附上初步答案。
4. **发现两处内容有关**：当前内容自动选中→按标题与摘要选另一段→说明理由。普通主题关联默认轻量，观点支持或冲突保留证据要求。

归档内容仍可作为公开关联端点，但不接收新回答或追问。撤回位置不出现在选择器中。失效、错误类型或错误所属问题的固定链接不能被静默换成别的位置。

## 自动收录与旧数据

- 新旧四种完整表单均可识别，包括用户改了 GitHub 顶层标题的情况；旧快照和已收录正文不改写。
- 保留字段顺序、完整公开确认、原文片段、目标版本与可见性校验；分别按新旧表单的字段识别 Markdown，避免新增标签破坏旧正文。
- 不依赖 GitHub 顶层 Issue 标题生成内容，因为现有来源快照不记录它的变更。
- 一条 Issue 仍只自动收录一次；重试不重复导入，收录后编辑不覆盖历史。最终写入前再次检查投稿位置。

## 当前边界与发布

仍需要 GitHub 账号，并跳转到 GitHub 提交。这是本轮简化后剩下的主要摩擦。GitHub 表单不能隐藏自动填入的位置，也不能按是否附带回答动态隐藏字段，因此保留两项通用选填内容；不在本站先收正文，避免随后重复粘贴或把正文塞进跳转 URL。

私有 Sites 预览只能更新网页，GitHub 表单与自动归集运行的是公开仓库默认分支代码。发布时必须把表单和解析器一起同步到公开仓库；只更新网页预览不意味着 GitHub 已切换新表单。

若下一步目标是完全站内提交、无需 GitHub 账号，需要单独实现持久化服务、身份或匿名投稿、反滥用与收录反馈。这是投稿方式的改变，不能靠删几个字段宣称已经完成。
