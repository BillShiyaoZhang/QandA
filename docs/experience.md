# 使用案例与用户体验梳理

更新：2026-09-06。本轮依据产品意图、页面实现和自动化验收做可用性审查，尚未进行真实用户访谈或试用。用户提出的问题是：每个问题的档案与“分支查看”展示相同内容，分支结构应成为默认入口。

## 信息架构与页面职责

首页“问题档案”用于发现和选择探索主题。打开一个问题，立即进入**分支图 + 当前节点阅读区**；图和目录只是同一份结构的两种显示方式。选择答案、追问或历史版本，在原工作区继续，不再要求先读一页列表再跳到另一页探索。

- `/questions/:id/`：默认工作区。普通访问定位本题；`?focus=:node` 精确定位问题、答案或历史修订。
- `/explore/:root/`：兼容旧分享链接，使用同一个工作区组件，避免两套功能继续分化。
- `/questions/:id/revisions/:revision/`：固定版本原文、修订说明、记录信息和完整关联证据；能返回对应分支。
- `/answers/:id/`：固定回答原文、来源、实际提问、生成条件和上下文。属于记录详情；能返回对应分支。
- `/compare/`：并排比较；返回时保留进入前的节点位置。
- `/contribute/`：显示投稿针对的内容，再进入 GitHub 正文表单。

关系应让读者看懂：“问题 → 多份平级回答 → 各自引出的追问”。只有一个可见当前版本时，问题与版本共用一个图中位置；多个版本、旧版本、撤回版本仍分别保留。这个变化只影响显示，不改变答案关联的实际修订和复制路径。

## 使用案例与本轮处理

| 用户要做什么 | 原来的阻碍 | 本轮体验与验收依据 |
| --- | --- | --- |
| 找到感兴趣的问题 | 档案页只强调正文和答案数，看不出进入后能探索分支 | 首页入口标为分支图，答案数明确覆盖本题全部版本 |
| 第一次进入一个问题 | 必须再点“查看探索树”；树初始还把答案藏在版本节点下 | 默认图显示问题、回答及首层追问；单版本合并显示 |
| 看清同题多答案 | UUID 占据大部分节点空间；同模型记录难以区分 | 答案显示来源名称和摘要；版本使用“第 N 版”，完整 ID 留在记录中 |
| 连续阅读一条分支 | 选节点后打开完整记录才能继续操作 | 阅读区直接提供追问、提交答案、比较、排序、注释、关联线索和记录详情 |
| 从最近追问进入 | 当前问题和起始问题的关系不明显 | 进入同一棵树并选中该追问，路径使用可读标题 |
| 搜索到一份答案或历史提问 | 搜索跳入另一个独立阅读入口；当前提问重复索引 | 搜索结果指向问题工作区并定位节点；当前版本只索引工作区，旧版保留独立索引 |
| 查看问题更新前的回答 | 切换至最新问题容易误解当时输入 | 回答仍挂在实际修订下，阅读区显示版本选择；复制路径保持原历史链 |
| 比较后继续探索 | 返回问题时丢失所选答案和版本 | 比较带上来源位置，返回原工作区节点；独立访问比较也能返回左侧答案 |
| 针对具体答案追问 | 进入投稿页后只剩父答案 ID | 投稿页显示问题标题、回答片段和返回分支链接，保持精确 ID 预填 |
| 理解跨分支线索 | 探索页完全没有关联入口 | 阅读区展示关联线索和理由，完整记录可查看片段与局部关联图 |
| 手机查看结构 | 树目录默认隐藏，进入后还是纯阅读 | 默认显示分支图；选节点后进入阅读，可明确切回分支 |
| 分享或回退 | 可定位但不易发现分享功能；深层节点不在图的可视范围 | 复制节点链接，保留前进后退；选择节点时同步滚动图内位置 |
| 空问题、归档、撤回 | 容易没有下一步，或只显示消失的正文 | 无回答有明确提示；归档保留阅读并关闭投稿；撤回保留历史位置与后续分支 |
| 网络失败或不用脚本 | 加载页没有内容；重试可能又回到同一加载页 | 初始提问与答案链接静态输出；树与节点分别可重试，失败可打开确切版本记录 |
| 浏览很多节点与深分支 | 页面一次塞入太多节点，或“更多”多次点击不变 | 首次最多 100 个节点，保留当前祖先链；“更多”逐步补充其他节点 |

## 交互约定

1. 图、目录、阅读区共用一个选中节点，切换显示方式不改变选中内容。
2. 普通链接保留新窗口打开能力；浏览器前进、后退、刷新和复制链接都恢复同一节点。
3. 初始页面已有可阅读内容，脚本增强结构和节点切换；网络错误不能冒充无内容。
4. 树的连接线只表示回答与追问的父子关系。横向关联作为独立线索展示，不并入生成上下文，也不暗示观点已核验。
5. 当前问题变更不迁移旧答案。单版本视觉合并不修改数据，不隐藏历史修订 ID 的访问能力。
6. 信息按任务展开：正文与继续操作在前，来源、参数、ID 与完整证据由详情承载。

## 尚需真实使用验证

本轮不把自动化测试当作用户研究。建议让首次访问者完成：从首页选题、指出两份平级答案、找到一个追问的父答案、比较后返回、提交追问并核对目标。记录是否需要解释、走错页面、找不到返回入口，以及 GitHub 跳转带来的放弃。

后续按真实反馈决定投入，避免继续堆入口：

| 优先级 | 待验证或后续改进 | 触发依据 |
| --- | --- | --- |
| P1 | 把局部横向关联图直接整合进工作区 | 读者经常跨树探索，现有线索和详情跳转明显打断阅读 |
| P1 | 投稿页内更完整的内容选择与目标校验 | 用户直接进入投稿页，而不是从已有节点发起，频繁需要手填 ID |
| P2 | 最近活动加入新回答，提供回访线索 | 内容增长后用户无法发现问题的新进展 |
| P2 | 大树的子树聚焦、缩略总览与更灵活图布局 | 默认连接图与折叠目录在真实规模下仍难以定位 |
| P2 | 站内投稿或更低门槛身份方式 | 实际贡献者明确因 GitHub 注册／跳转放弃 |

实现与测试细节见 [实现说明](implementation.md) 和 [验证记录](verification.md)。
